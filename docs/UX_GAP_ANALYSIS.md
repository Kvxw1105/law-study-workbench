# 体验差距分析与设计思考：挖空 / 闪卡 / 主动建卡

> 目的：作为用户真实使用反馈的整理稿，供工程讨论与排期。基于当前代码事实（commit d6eec50），不涉及"要不要引入大模型"的路线问题——以下全部可在本地规则框架内实现。

## 1. 用户反馈的核心问题

1. **挖空与闪卡提问方式几乎一样**：同一句教材原文，挖空挖掉一个词、闪卡却让你"复述这整句"——两者视角重复，看不出各自该干什么。
2. **挖空没有上下文**：呈现的是孤零零一句（甚至半句），读者无法"根据上下文回想"，只能干瞪眼。
3. **没有"想不起来看答案"的流畅体验**：reveal 存在但只显示"答案+单句来源"，没有回到原文段落、没有高亮挖空位置。
4. **没有用户主动建卡**：无法像思源笔记那样"划选文本 → 标记 → 变成挖空"。唯一的手动入口是藏在单元操作里的空白"建立提取卡片"表单（填 prompt/answer），与用户心智不符。
5. **闪卡提问方式粗糙**：只有"什么是X？""X包括哪些内容？"两个模板，其余全部落到兜底"请完整说明「标题」中的规则：<把原文原样贴出来>"。

## 3. 设计思考

### 3.1 先重新定义两种卡片的语义（信息架构）

这是"提问方式相同"的根治——先定语义，再谈实现：

- **挖空 = 提取型记忆（recall of specifics）**：呈现**完整段落**（上下文），中间空出**确定性知识点**（术语/要件/数字/日期/法定名称）。读者凭上下文回想；想不起 → 点开显示答案，并回到原文段落看到这个空在原文哪里。
  - 判据：挖空答案必须是"上下文可推断的确定性内容"。一句话里挖一个 5 字名词却没有任何上下文提示，就是无效挖空。
- **闪卡 = 结构复述（recall of structure）**：呈现**一个提问角度**（是什么/为什么/包括哪些/构成要件/区别/例外/法律依据…），读者用自己的话组织回答。答案是结构化的要点，**prompt 不应把原文原样贴出**（否则变成背课文）。

**原则：同一素材句不应同时既被挖空又被闪卡。** 生成时按句子类型分流（见 3.4）。

### 3.2 用户主动建卡（最高优先级，思源式交互）

目标交互：**在教材正文上直接划选建卡**。

1. 单元正文视图（现 `unitDialog` 已能看正文）改为**可选择文本**。
2. 鼠标划选（触屏长按）弹出浮动操作条：**「挖空」「闪卡」**。
3. 选「挖空」：选中文本即成为空。本地用 `==内容==` 标记表达（思源兼容语法），**保存后原文标注保留**——教材来源里能看到"原文 + 标记"，证据链完整。
4. 支持**多空**：同一句里可以划多个 `== ==`（当前代码只支持单空，需扩展）。
5. 选「闪卡」：弹出问题模板选择（见 3.5），确定问题角度后生成。
6. 编辑模式兼容：用户也可直接在正文编辑框里手写 `== ==` 语法建卡（不依赖鼠标）。

约束：用户建卡是本地操作，不违反零 token / 证据不可伪造；新卡片按现有协议生成 content_hash，存量卡片不受影响。

### 3.3 挖空形态改造

- **学习时**：挖空卡呈现"前后文（≥ 完整句，最好到段落边界）+ 空"，而不是单句。段落上下文来自单元 body 的定位（记录 sentence 在 body 中的偏移，或存上下文摘录字段）。
- **reveal 增强**：点"显示答案"除了 answer，还要：①显示该句所在的完整段落；②在段落里标亮答案位置（高亮 or 括号标注）；③显示页码/原文位置。
- 数据模型：cloze 卡片增加 `context_prefix`/`context_suffix`（或存 `source_offset`），reveal 返回时按需组装——需评估对 Study Protocol 0.1 哈希链的影响（建议新增字段走新版本哈希，不破坏存量）。

### 3.4 挖空/闪卡素材分流（解决"提问方式一样"）

生成时不再共用同一批句子，而是按句子特征分流：

- 含"是指/包括/应当/必须/不得/要件/条件/标准/期限…"且结构完整的句子 → **挖空池**（适合提取知识点）
- 含"为什么/因为/所以/区别/例外/意义/目的…"或结构性论述句 → **闪卡池**（适合复述逻辑）
- 同一句两端都够格时：只生成一种，避免重复视角。

### 3.5 闪卡模板库多样化

把 2 个模板扩成**一组可枚举的问题类型**，用关键词启发式匹配 + 用户建卡时手动选择：

| 类型 | 示例 prompt | 启发式信号 |
| --- | --- | --- |
| 定义 | 什么是{概念}？ | 含"是指/系指/即/定义为" |
| 构成要件 | {制度}的构成要件有哪些？ | 含"要件/必须具备/应当具备" |
| 条件 | {规则}的适用条件是什么？ | 含"条件/前提/须/必须" |
| 分类 | {概念}分为哪几类？ | 含"分为/包括/种类" |
| 区别 | {A}与{B}有何区别？ | 含"区别于/不同于/与…不同" |
| 例外 | {规则}的例外情形有哪些？ | 含"例外/除外/但书/不得" |
| 依据 | {规则}的法律依据是什么？ | 含"依据/根据/规定" |
| 意义 | {制度}的意义是什么？ | 含"意义/作用/价值/目的" |
| 兜底 | 用自己的话复述：{主题}（不贴原文） | 其余 |

### 3.6 已有功能盘点（避免重复造轮子）

- ✅ reveal 端点 + UI 按钮已有 → 只需增强返回内容（整段+高亮）
- ✅ 手动建卡表单已有 → 需要的是"从划选带入"而非新建表单
- ✅ 卡片版本/复测/证据记录已有 → 挂新交互即可
- ❌ 划选交互、多空、模板库、挖空上下文字段 → 需新建

## 4. 优先级建议

- **P0（体验核心）**：正文划选建卡（挖空+闪卡）、多空支持、挖空带段落上下文
- **P1**：reveal 增强（整段+高亮+页码）、闪卡模板库、挖空/闪卡素材分流
- **P2**：卡片编辑/停用/替换的流畅 UI、模板手动选择入库

## 5. 与现有约束的兼容性

- 本地优先、零 token：全部可本地实现 ✓
- 证据不可伪造：用户建卡/标记属于"学习者的主动操作"，比规则生成更符合证据语义 ✓
- Study Protocol 0.1：新字段/新模板需走 content_hash 新版本，存量卡片不受影响 ✓
