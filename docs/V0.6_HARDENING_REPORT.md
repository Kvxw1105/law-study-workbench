# v0.6.0 法学学习真实性硬化报告

状态：`LOCALLY_VERIFIED / REAL_USER_ALPHA_PENDING`

数据库：SQLite Schema 3（未升级）

## 目标

v0.6.0 不扩张“法学智能”名词，集中修复 v0.5.0 产品真实性审计中最影响真实学习的三类问题：关键法律信息被相似度平滑、知识单元边界不可人工治理、错误只有记录没有修复闭环。

## 1. 法学关键冲突闸门

新增 `app/services/legal_signals.py`，在字符串相似度之前检查高风险法律信号：

- 允许/禁止与义务极性：应当/不应当、可以/不得/不可以、必须/无需等；
- 效力与成立方向：有效/无效、生效/不生效、成立/不成立、发生效力/不发生效力；
- 权限、责任、适用与取得方向；
- 善意/恶意；
- 期限、数字与单位；
- 常见法律主体冲突。

单空挖空命中关键冲突时固定进入 `again`，分数上限 45，并显示冲突原因。关键项不能再因文本高度相似进入 `hard`。

## 2. 五维“法学诊断”降级为来源恢复检查

`law_full_recall_v1` 升级到 `0.2.0`。五维结构仍用于训练导航，但其数值被明确限定为“本地来源恢复信号”。

新增两种状态：

- `critical_conflict`：来源句与回答在关键限定、数字、主体或结论方向上发生冲突；
- `uncertain`：字面证据无法安全判断语义，例如关键词堆砌或低重合的完整改写。

持久化标记增加：

```json
{
  "lexical_source_signal": true,
  "semantic_correctness_verified": false,
  "formal_legal_grade": false
}
```

因此高分只表示来源字面恢复较强，不再被界面描述成法学结论已验证。

## 3. KnowledgeUnit 审核器

教材库新增“审核 / 编辑”工作流：

- 修改标题、正文、学习材质；
- 保存为草稿或“保存并确认”；
- 按正文光标拆分；
- 合并当前教材中相邻知识单元。

结构调整采用“归档旧单元 + 新建草稿单元”。历史 `attempts`、`retrieval_attempts`、来源和旧单元 ID 均不迁移、不重写。受影响活动卡片进入 `stale`。

归档单元仍可作为历史证据查询，但已经从今日复测、当前掌握统计、错因修复队列和活动卡片队列中排除，也不能再直接启动学习或建立新卡片。

当前拆分仍继承父单元的页码范围；精确段落/坐标级来源重映射尚未实现，这是后续 SourceChunk 层的工作。

## 4. 错因修复闭环

`error_records` 在不升级 Schema 的前提下启用已有 `status/resolved_at` 字段：

`open → repairing → resolved`

规则：

1. 用户从“学习证据”启动针对性修复；
2. 系统冻结 `error_repair_started` 事件与本轮 `session_id`；
3. 必须在该修复会话中完成新的 `hint_level=0` 完整闭卷；
4. 系统只标记“可确认解决”，不会因启发式分数自动关闭；
5. 用户人工确认后写入 `resolved_at` 与 `error_resolved` 事件。

这是一条真实状态闭环，但目前仍是“错误实例修复”，尚未完成跨题目的语义根因聚类。

## 5. 对抗与回归证据

新增/扩展测试覆盖：

- 应当 ↔ 不应当；
- 可以 ↔ 不可以/不得；
- 三十日 ↔ 六十日；
- 善意 ↔ 恶意；
- 高字面重合但法律效果反向；
- 关键词堆砌不再被当作可靠语义答案；
- 拆分/合并保留历史 Attempt 并使旧卡片 stale；
- 归档知识单元不再进入当前任务队列；
- 修复前、修复中、完成无提示复测、人工关闭的状态约束；
- 真实 HTTP 中的关键冲突与错因修复链；
- Chromium 中的知识单元审核器与错因修复队列。

当前全套：`25 passed`，并通过 compileall、JS 语法、HTTP、备份恢复与浏览器回归。

## 仍不能声称的能力

- 不能声称五维来源恢复检查等价于法学阅卷评分；
- 不能证明任意同义改写语义正确；
- 不能完成完整争点识别、事实—要件涵摄或法条效力核验；
- 不能自动把多个错误聚类为稳定认知根因；
- 不能自动确定知识单元拆分点；人工审核器只是把纠错权交还给用户；
- 不能提供段落/字符坐标级 PDF 高亮来源。

这些边界是 v0.6.0 的产品契约，而非待隐藏的缺陷。
