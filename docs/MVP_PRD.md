# MVP PRD：法学语义学习工作台 v0.2

## 产品定义

一个本地优先、证据驱动的应试学习工作台，将用户教材转换为可追溯的知识单元，通过完整闭卷、闪卡、挖空、来源对照、错因诊断和间隔复测，让用户持续证明自己已经掌握。

## 第一用户

当前第一用户是产品创建者本人：主要使用本地电子教材准备法学考研，重视语义结构、精确复现、题眼链接、规范表达和错因修复。

公共版本首要服务使用电子教材、需要主动提取和复测的高强度应试学习者。

## 真实完成点

```text
导入本地 PDF
→ 解析质量可见
→ 知识单元可用
→ 用户完成一次完整闭卷或卡片提取
→ 反馈可回到教材页码
→ 作答与复习状态写入本地
→ 下一次复测被安排
→ 应用重启后恢复
→ 新证据更新掌握状态
```

生成了讲义、卡片或索引只属于中间产物。用户完成真实提取并形成下一步任务，才算一次有效学习闭环。

## v0.2 目标

1. 保持 v0.1 的本地教材、完整闭卷、错因和复测闭环。
2. 增加适合条件、术语和规则节点的短时主动提取能力。
3. 让闪卡和挖空拥有独立作答证据、到期时间和重启恢复状态。
4. 保证自动生成内容可核对、可编辑、可停用，知识单元变更后不会继续使用旧卡。
5. 继续保持模型可替换、数据可导出和核心路径离线可用。

## v0.2 非目标

- 不建设通用人格型长期记忆。
- 不上传并托管整本教材。
- 不承诺扫描 PDF 全自动 OCR。
- 不把本地覆盖评分包装成正式考试评分。
- 不把自动卡片包装成权威题库。
- 不实现多人、教师后台、社区和题库市场。
- 不实现多 Agent 自主协作。
- 不强制本地大模型或云端模型。
- 不在本版本实现多空联动、同义答案组、FSRS 和移动端完整功能。

## 核心页面

### 今日学习

显示未完成完整闭卷、到期知识单元、到期卡片、今日完整作答和今日卡片提取。主动作聚焦继续、复测或开始新单元。

### 本地教材库

导入 PDF，查看解析状态、低文本页面、知识单元和页码。每个知识单元可开始完整闭卷、生成挖空与闪卡或练习已有卡片。

### 闭卷学习

默认隐藏原文；支持答案、置信度、计时、草稿恢复、分级提示和来源对照。提交后生成完整闭卷证据、错因和知识单元级复测。

### 挖空与闪卡

- 卡片中心：到期数量、闪卡/挖空数量、今日提取和管理列表。
- 闪卡：先尝试回忆，主动揭示答案，再选择忘记、困难、记得或轻松。
- 挖空：填写被隐藏的术语或规则片段，提交后本地核对并显示答案与来源。
- 卡片管理：从知识单元手动新建、查看答案与来源、编辑、停用和单卡练习。

### 学习者模型

分别展示完整闭卷和卡片提取的真实证据。结论来自结构化作答，不依赖聊天摘要。

### 设置与数据

保存明确学习目标、显示模型隐私状态、导出全部结构化学习数据；外部脚本负责完整备份和受控恢复。

## 关键业务规则

- 同时只允许一个活动完整闭卷会话。
- 未提交答案不生成完整闭卷掌握证据。
- 闪卡练习接口默认不返回答案；服务端必须确认本轮已揭示答案后才允许评分，一次揭示只能提交一次。
- 挖空提交后才能显示标准答案与来源。
- 每张卡片独立保存作答和复测状态。
- 相同知识单元中的相同卡片按内容哈希去重。
- 用户编辑卡片题面、答案或来源后，该卡片重置为新卡；历史作答保留当时的题面、答案、来源、内容哈希和卡片版本快照。
- 用户主动停用的卡片不进入队列，也不会被自动生成重新启用。
- 知识单元正文或标题变化后，旧活动卡进入 `stale`；重新生成时只重新启用仍与当前内容一致的 stale 卡。
- 相同 PDF 内容哈希只建立一个来源记录。
- 云端 Provider 失败时，可降级到本地评分并明确告知。
- 重启后完整闭卷草稿、卡片作答历史和到期状态必须恢复。

## 当前复测规则

### 知识单元级完整闭卷

- 高置信度低分：次日复测，优先辨析。
- 有效分数较高：七日后再次完整闭卷，检验延迟保持。
- 中等：三日复测并补齐遗漏。
- 较低：次日无提示重答。

### 卡片级短提取

- 忘记：约 10 分钟后再测，连续成功清零，遗忘次数增加。
- 困难：约 1 天后再测。
- 记得：首次约 3 天，后续按当前间隔扩展。
- 轻松：首次约 7 天，后续更快扩展。

两套规则均为可解释的产品假设，必须由真实学习数据校准。

## 验收场景

1. 导入一份文字型 PDF，生成带页码的知识单元。
2. 从知识单元本地生成闪卡和挖空，重复生成不创建重复卡。
3. 闪卡未显示答案时提交评分被拒绝；显示答案后可四档自评。
4. 挖空准确答案获得高分，错误答案进入短间隔复测。
5. 完成卡片后，今日任务、学习者模型和导出数据同步更新。
6. 关闭并重启应用，卡片到期时间、连续成功和历史作答保持。
7. 修改知识单元后旧卡变为 stale；再次生成时可恢复仍有效的卡。
8. 编辑卡片后复习状态重置；停用后不再进入队列。
9. 原有完整闭卷、错因、提示权重、草稿恢复和单一活动会话继续工作。
10. Schema 1/2/3 数据库升级到 Schema 4 后，既有教材和历史作答不丢失；无法精确重建的 legacy 快照必须带明确来源状态，旧 ReviewState 不能未经证明继承到当前证据版本。
11. JSON 导出和完整备份包含新增卡片相关表。
12. 无网络时，本地教材、完整闭卷、本地评分、挖空、闪卡和复习均可使用。
13. 完整闭卷 Session 冻结 KnowledgeUnit version/body_hash/material snapshot；正文或学习目标改版后，新版本重新形成掌握证据。
14. Hard Conflict 必须进入有效证据裁决并真实影响 ReviewState/调度；Possible Conflict 保守进入待核验。
15. 错因修复只有在对应 repair session 的新无提示 accepted evidence 达门后才允许人工确认关闭。

## 成功指标候选

Alpha 期间采集：

- 首次导入到第一次有效提取的时间。
- 自动生成卡片的保留率、编辑率和停用率。
- 每个知识单元平均有效卡片数。
- 卡片到期完成率与再次遗忘率。
- 完整闭卷与卡片短提取的时间分配。
- 即时结果和 1/3/7 日延迟复测差距。
- 高置信度错误率和提示依赖变化。
- 崩溃、关闭和重启后的恢复成功率。
- 每次有效学习会话的云端成本。

## 下一里程碑

### M1：真实教材个人 Alpha

使用一章真实法学教材完成约 30 次完整闭卷和卡片提取，记录低质量卡片、遗漏类型和真实复测结果。

增加专用建卡表单、多空挖空、同义答案组、法条数字模板、FTS5、页块高亮和来源修复。
