# 产品不变量

这些原则高于单个页面、模型、框架和商业功能。后续开发若与其冲突，必须先修改产品定义并形成显式迁移方案。

## 1. 数据归属

教材原文件、解析结果、用户答案、卡片、学习状态、错因和复测记录默认保存在本机。云端服务不得把整本教材上传设为核心学习流程的前提。

## 2. 记忆属于产品

学习证据画像及未来学习者模型都由结构化学习证据构成，不能依赖某家模型供应商的聊天记忆。模型可替换，学习历史、稳定 ID 和来源关系必须保留。

## 3. 掌握必须有证据

没有真实作答，不宣布掌握。提示后答对、看过原文后答对、闪卡揭示答案后的自评、挖空即时答对和延迟无提示答对，证据权重与含义必须区分。

完整闭卷至少记录答案、置信度、用时、提示级别、来源覆盖和复测；卡片至少记录题型、回答或自评、用时、是否揭示答案、得分、间隔和到期时间。

完整闭卷证据还必须绑定当时的 KnowledgeUnit 版本、正文哈希、学习目标和材料快照。正文或学习目标变化后，旧掌握不得自动继承到新证据版本；历史 Attempt 不得用当前正文重新解释。

## 4. 原文、生成物与推断分离

教材原文、自动生成卡片、确定性规则结果、AI 评分、AI 推断和用户确认必须能被区分。每个重要反馈和卡片应能回到知识单元与教材页码。

## 5. 卡片是可审查的派生数据

自动生成只提供初稿。卡片必须可查看答案与来源、可编辑、可停用，并记录生成方法和版本。知识单元发生实质变化后，旧活动卡不得继续进入复习队列。

## 6. 云端只接收最小上下文

启用云端 Provider 时，只发送当前任务所需的知识单元、当前答案和少量相关错误。原始 PDF、完整数据库和无关历史记录不进入默认上下文。

## 7. 确定性流程约束 Agent

闭卷前不得自动展示完整答案；闪卡未揭示答案时不得评分；未提交作答时不得生成掌握证据。Agent 不得自由修改数据库、方法规则或来源内容。确定性状态机负责边界，模型负责局部判断。

## 8. 单一进行中完整闭卷

同一时间只允许一个活动完整闭卷会话，避免多个未完成任务污染计时、草稿和提示证据。卡片队列是短任务，可显式结束，不应改写完整闭卷会话。

## 9. 可解释、可纠正、可撤销

用户能够看到系统为什么形成某个学习判断。AI 推断不得无证据固化为永久标签。卡片编辑、停用、数据迁移、恢复和 Agent 写操作必须有回执与回滚路径。

## 10. 本地失败可恢复

索引、自动卡片和其他派生内容可以重建；用户原始作答、卡片历史、错因、复测记录和来源版本不能因解析器升级而丢失。中断后应恢复完整闭卷草稿和卡片复习状态。

## 11. 用户主动停用优先

用户标记为 `archived` 的卡片不得被批量生成或自动修复静默复活。系统可重新启用因知识单元变化进入 `stale`、且与当前来源仍一致的卡片，并必须重置其复习状态。

## 12. 学习结果优先于系统复杂度

产品首先减少从打开应用到完成一次有效提取的距离。聊天、图谱、多 Agent、游戏化和海量生成内容均属于条件功能，不能遮蔽今日任务与真实作答。
